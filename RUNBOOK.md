# ReqCheck — Runbook

Инструкция по установке, запуску, тестированию и устранению проблем.

## 1. Требования

- Python 3.10 или новее (проект проверялся на Python 3.12).
- Для AI-анализа: ключ Google Gemini API.
- Для AI-анализа: подключение к интернету.
- Для rule-based режима и автоматических тестов: API-ключ и интернет не требуются.

Получить API-ключ можно в [Google AI Studio](https://aistudio.google.com/apikey).

Доступность бесплатной квоты зависит от модели, региона и текущих ограничений Google. Перед запуском проверьте актуальные лимиты в Google AI Studio.

## 2. Установка

Клонируйте репозиторий и перейдите в его корневую папку:

```bash
git clone https://github.com/E7aman/reqcheck.git
cd reqcheck
```

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его.

**Windows PowerShell:**

```powershell
.venv\Scripts\Activate.ps1
```

**Windows CMD:**

```cmd
.venv\Scripts\activate.bat
```

**Linux / macOS:**

```bash
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

### Настройка API-ключа

Если в репозитории есть файл `.env.example`, создайте на его основе `.env`:

**Windows CMD:**

```cmd
copy .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

Откройте `.env` и укажите ключ:

```env
GEMINI_API_KEY=your_api_key_here
```

Также поддерживается переменная `GOOGLE_API_KEY`.

Файл `.env` содержит секретные данные и не должен попадать в Git.

## 3. Запуск агента

Запустите анализ тестового документа:

```bash
python -m validator tests/fixtures/requirements.md out/report.md --json out/result.json
```

Аргументы:

- `tests/fixtures/requirements.md` — входной документ с требованиями.
- `out/report.md` — путь для Markdown-отчёта.
- `--json out/result.json` — дополнительный путь для JSON-результата.

Папка для отчёта создаётся автоматически.

Можно использовать собственные документы в форматах `.md`, `.markdown`, `.txt`, `.pdf` и `.docx`.

### Полезные параметры

| Флаг | Назначение |
| --- | --- |
| `--json out/result.json` | Дополнительно сохраняет результат в JSON |
| `--lint-only` | Запускает только структурные и rule-based проверки |
| `--no-verify` | Пропускает этап самопроверки AI-находок |
| `--no-cache` | Отключает использование кеша ответов модели |
| `--min-interval 8` | Устанавливает минимальную паузу между запросами в секундах |
| `--model <имя>` | Выбирает модель Gemini или список резервных моделей через запятую |

Для просмотра всех доступных параметров:

```bash
python -m validator --help
```

### Rule-based режим

Для запуска без API-ключа:

```bash
python -m validator tests/fixtures/requirements.md out/report.md --lint-only
```

Этот режим выполняет детерминированные проверки без обращения к языковой модели.

### Результаты работы

В примере выше создаются:

- `out/report.md` — подробный отчёт в Markdown.
- `out/result.json` — структурированные результаты анализа.

Отчёт содержит паспорт прогона, результаты извлечения требований, индивидуальные и общие замечания, анализ структуры документа, сводку и рекомендации.

### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | Успешное выполнение или завершение с предупреждением о частичном результате |
| `2` | Ошибка входных данных или конфигурации |
| `3` | Критическая ошибка API или недоступность модели |

При частичном выполнении внимательно проверяйте предупреждения в консоли и самом отчёте.

### Ограничения API

Количество запросов зависит от размера документа, этапов анализа, кеша и выбранной модели.

При исчерпании квоты агент прекращает дальнейшие обращения к модели и формирует частичный отчёт с соответствующим предупреждением.

Особенности работы:

- Выполненные этапы сохраняются в кеше.
- При повторном запуске доступные результаты могут использоваться повторно.
- Кеш привязан к названию модели.
- При смене модели соответствующие этапы могут потребовать повторного выполнения.
- Резервные модели можно указать через `GEMINI_MODEL` или параметр `--model`.
- Ошибки временной недоступности сервиса могут приводить к повторным запросам.

Если квота исчерпана, можно дождаться её восстановления или выбрать другую доступную модель.

## 4. Автоматические тесты

Запустите тестовый набор из корня репозитория:

```bash
python -m unittest discover -s tests -t . -v
```

Последний контрольный прогон:

```text
Ran 54 tests
OK (skipped=1)
```

Результат зависит от установленного окружения. Один тест может быть пропущен, если отсутствует необходимый системный шрифт для создания PDF.

### Что проверяют тесты

- Загрузку и обработку документов.
- Извлечение текста и поиск цитат.
- Структурные проверки и защиту от ложных срабатываний.
- Извлечение и идентификацию требований.
- Объединение результатов rule-based и AI-анализа.
- Проверку цитат и удаление неподтверждённых находок.
- Матрицу покрытия критериев приёмки.
- Обработку ошибок API, повторные запросы и резервные модели.
- Устойчивость конвейера к некорректным ответам модели.
- Работу CLI и формирование отчётов.

Тесты используют подставную модель и не расходуют квоту Gemini.

### PDF-тест

Для теста создания PDF необходимы:

- библиотека `reportlab`;
- доступный системе шрифт с поддержкой кириллицы, например DejaVu Sans.

Установка библиотеки:

```bash
pip install reportlab
```

Если тест сообщает `нет шрифта с кириллицей`, это означает, что подходящий шрифт не найден в текущем окружении. Сам тест не выполняется, но остальные тесты продолжают работать.

DOCX-тест проверяется отдельно и не зависит от этого PDF-шрифта.

## 5. Оценка качества агента

После AI-прогона с параметром `--json` можно сравнить результаты с эталонным набором дефектов:

```bash
python -m validator.evaluate out/result.json tests/gold/requirements_gold.json
```

Оценщик показывает, сколько эталонных дефектов найдено, а также какие из них были пропущены.

Рабочий цикл улучшения:

1. Запустить анализ документа.
2. Сравнить результат с эталоном.
3. Изучить пропущенные и ошибочно найденные дефекты.
4. При необходимости скорректировать промпты в `validator/prompts.py`.
5. Повторить анализ с `--no-cache`, чтобы получить новые ответы модели.

Эталонный набор составлен вручную и сам может требовать проверки и дополнения.

## 6. Проверка на чистой машине

Перед передачей проекта рекомендуется выполнить независимую проверку:

1. Склонировать репозиторий в новую папку или на другой компьютер.
2. Установить зависимости по разделу 2.
3. Настроить собственный API-ключ для AI-анализа.
4. Запустить пример из раздела 3.
5. Убедиться, что отчёт создан и секретные данные не попали в него.
6. Запустить тесты из раздела 4.
7. Проверить работу `--lint-only` без API-ключа.

Цель проверки — убедиться, что проект запускается по документации без использования локальных настроек разработчика.

## 7. Устранение проблем

| Симптом | Возможное решение |
| --- | --- |
| `не задан GEMINI_API_KEY` | Проверьте `.env`, имя переменной и текущую рабочую папку |
| `не установлен google-genai` | Активируйте виртуальное окружение и выполните `pip install -r requirements.txt` |
| `повтор через N с` | Возможны ограничения API или временный сетевой сбой; при необходимости увеличьте `--min-interval` |
| `Gemini вернул ошибку 404` | Проверьте название модели и её доступность |
| `Gemini вернул ошибку 401` | Проверьте API-ключ и его действительность |
| `Gemini вернул ошибку 403` | Проверьте доступ к API и состояние проекта в Google AI Studio |
| `429 RESOURCE_EXHAUSTED` | Вероятно, исчерпана доступная квота; дождитесь её восстановления или выберите другую модель |
| `503 high demand` | Временная перегрузка сервиса; повторите запуск позднее |
| `Не выполнены этапы: ...` | Отчёт может быть частичным; изучите предупреждения и повторите запуск |
| `В PDF не найден текстовый слой` | Документ может быть сканом; используйте PDF с текстовым слоем или другой поддерживаемый формат |
| PDF-тест пропущен из-за отсутствия шрифта | Установите шрифт с поддержкой кириллицы, например DejaVu Sans |
| Повторно появляется старый результат | Проверьте кеш `.llm_cache/`; используйте `--no-cache` для нового анализа |

---

**Важно:** ReqCheck — инструмент поддержки проверки требований, а не замена экспертной оценки. Все результаты AI-анализа должны быть проверены человеком.
