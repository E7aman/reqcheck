# Инструкция по запуску и тестам

## 1. Что нужно
- Python 3.10 или новее (проверено на 3.12).
- Ключ Gemini API: https://aistudio.google.com/apikey (бесплатного тарифа хватает).
- Интернет для вызовов модели. Тесты и режим `--lint-only` работают без сети и без ключа.

## 2. Установка
```bash
cd reqcheck                        # корень репозитория
python -m venv .venv
source .venv/bin/activate          # Windows (cmd): .venv\Scripts\activate
pip install -r requirements.txt
```

Ключ:
```bash
cp .env.example .env               # Windows (cmd): copy .env.example .env
```
Откройте `.env` и впишите значение в `GEMINI_API_KEY=`. Файл `.env` в git не попадает.

## 3. Запуск агента
```bash
python -m validator tests/fixtures/requirements.md out/report.md
```
Первый аргумент — файл с требованиями (`.md`, `.txt`, `.pdf`, `.docx`), второй — куда записать отчёт. Папка для отчёта создаётся сама. Ход работы виден в консоли; на документе размером с тестовый прогон занимает порядка минуты-двух из-за пауз между запросами.

Полезные флаги:

| Флаг | Что делает |
| --- | --- |
| `--json out/result.json` | дополнительно сохраняет результат в JSON (нужен для оценки) |
| `--lint-only` | только структурные проверки, без LLM; ключ и сеть не нужны |
| `--no-verify` | пропустить этап самопроверки находок (быстрее, но больше ложных срабатываний) |
| `--no-cache` | не использовать кеш ответов модели |
| `--min-interval 8` | пауза между запросами в секундах (если упираетесь в лимиты) |
| `--model <имя>` | другая модель Gemini или несколько через запятую (резервные); то же задаёт `GEMINI_MODEL` в `.env` |

Результат: отчёт в Markdown по структуре из ТЗ (паспорт прогона, таблица нарезки, проверка каждого требования, проверка набора, структура документа, сводка, итог).

Коды выхода: `0` успех, `2` ошибка входа или настройки (нет файла, формат, нет ключа), `3` модель недоступна.

### Лимиты бесплатного тарифа
У бесплатного ключа есть суточный лимит запросов на каждую модель (для `gemini-3.8-flash` на момент написания — 20 в сутки; смотрите актуальные цифры в Google AI Studio). Один прогон на тестовом документе делает около 8–10 запросов.
- При исчерпании квоты агент сразу прекращает обращаться к модели и записывает **частичный отчёт** с пометкой. Повторный прогон позже подхватит выполненные этапы из кеша и не потратит на них квоту.
- Кеш привязан к строке модели: если вы меняете `GEMINI_MODEL`, этапы выполняются заново.
- Чтобы не упираться в лимит: укажите резервные модели через запятую, подождите сброса квоты или включите оплату в Google AI Studio (объёмы этого проекта стоят копейки).
- Ошибка `503 … high demand` временная: агент повторяет запрос сам.

## 4. Тесты
```bash
python -m unittest discover -s tests -t . -v
```
Ожидается: `Ran 54 tests ... OK`. Ключ и интернет не нужны: модель в тестах подставная.

Что покрыто: чтение md/PDF/DOCX и поиск цитат, структурные проверки (в том числе на ложные срабатывания), весь конвейер на подставной модели (отсев выдуманных цитат, самопроверка, матрица покрытия, структура отчёта), повторы и разбор JSON, CLI.

Если тесты PDF и DOCX помечены как пропущенные (`skipped`), это нормально: для PDF-теста нужны `reportlab` (`pip install reportlab`) и шрифт DejaVu в системе.

## 5. Оценка качества агента
После прогона с `--json` сверьте находки с эталонным списком дефектов:
```bash
python -m validator.evaluate out/result.json tests/gold/requirements_gold.json
```
Вывод: сколько эталонных дефектов найдено из 20 и какие пропущены. Рабочий цикл: прогон → оценка → правка промптов в `validator/prompts.py` → повторный прогон (с `--no-cache`, иначе вернётся старый ответ).
Эталон составлен вручную: перечитайте и дополните его сами.

## 6. Проверка «как у жюри» (чистая машина)
1. Склонируйте репозиторий в пустую папку или на другой компьютер.
2. Пройдите разделы 2–3 по этой инструкции, ничего не додумывая.
3. Убедитесь, что отчёт создался и в нём нет ключа.
4. Запустите тесты (раздел 4).

## 7. Если что-то не работает

| Симптом | Что делать |
| --- | --- |
| `Ошибка: не задан GEMINI_API_KEY` | проверьте `.env` и что запускаете из папки проекта |
| `не установлен google-genai` | `pip install -r requirements.txt` в активированном окружении |
| сообщения `повтор через N с` | сработали лимиты или сбой сети; агент повторяет сам. Если часто — `--min-interval 10` |
| `Gemini вернул ошибку 404 … повторы не помогут` | модель снята или имя неверно; задайте актуальную через `GEMINI_MODEL` в `.env` или `--model` (список в AI Studio) |
| `Gemini вернул ошибку 401/403` | неверный ключ или нет прав; проверьте `GEMINI_API_KEY` |
| `Исчерпана суточная квота Gemini` / `429 RESOURCE_EXHAUSTED` | дневной лимит; см. «Лимиты бесплатного тарифа» выше |
| `503 … high demand` | перегрузка на стороне Google; агент повторяет сам, при неудаче перезапустите через несколько минут |
| в отчёте `Не выполнены этапы: …` | часть этапов упала, отчёт неполный; перезапустите (кеш не потеряет выполненное) |
| `В PDF не найден текстовый слой` | это скан; OCR не поддерживается, нужен PDF с текстом или `.docx` / `.md` |
| прогон повторяет старый результат | это кеш (`.llm_cache/`); добавьте `--no-cache` или удалите папку |
